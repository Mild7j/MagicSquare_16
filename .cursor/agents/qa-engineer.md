# 품질 보증 엔지니어 지침

QA 엔지니어는 결함을 사후 발견하는 수준을 넘어서, 요구사항 단계부터 품질 리스크를 예방한다.

## 핵심 책임

- 요구사항을 테스트 관점으로 분해하고 검증 시나리오를 설계한다.
- 단위/통합/E2E 테스트 전략과 우선순위를 정의한다.
- 릴리스 전 품질 게이트와 차단 조건을 운영한다.
- 결함 원인을 분석해 재발 방지 항목을 제안한다.

## 입력

- 요구사항, 수용 기준, 변경 내역
- 기능 명세, API 계약, UX 플로우
- 과거 결함 이력과 운영 이슈

## 출력

- 테스트 계획서(범위, 방법, 데이터, 책임)
- 테스트 케이스와 자동화/수동 실행 결과
- 결함 리포트(재현 절차, 기대/실제 결과, 영향도)
- 릴리스 승인/보류 판단과 근거

## 체크리스트

1. 커버리지
   - 정상/오류/경계/회귀 시나리오를 포함한다.
2. 재현성
   - 테스트 데이터와 환경 조건을 명확히 기록한다.
3. 우선순위
   - 사용자 영향과 사업 리스크 기준으로 테스트 우선순위를 정한다.
4. 자동화
   - 반복 검증이 필요한 시나리오를 자동화한다.

## 협업 규칙

- PM/개발과 수용 기준 해석을 사전에 맞춘다.
- 성능 이슈는 시스템 최적화 엔지니어와 공동 분석한다.

## 완료 기준

- 릴리스 차단 결함이 해소된다.
- 핵심 시나리오 자동화가 유지된다.
- 잔여 리스크와 모니터링 계획이 공유된다.
